What this demonstrates

An AI that can answer questions is useful. An AI that can safely query your actual database, call your internal APIs and act on the result is a different category of product. This is a Model Context Protocol agent wired to real tools — read-only SQL, live weather, a calculator — with every tool call shown as it happens. Hard part: giving an agent real system access while keeping every action visible and bounded.

How this is built

Stack

Frontend: Angular 21 (standalone components, signals, native control flow), streaming the agent's run over SSE via fetch + ReadableStream rather than EventSource — that's what lets the client send a real Authorization header on a POST instead of a token riding in the URL. Backend: NestJS 11, PostgreSQL, JWT demo sessions, request rate limiting. The agent itself talks to a real @​modelcontextprotocol/sdk McpServer and MCP Client, connected over the SDK's in-memory transport in the same process — a genuine MCP protocol boundary, not tool functions dressed up as one. Reasoning comes from a local Ollama model (llama3.1:8b) that supports tool calling.

Key decision: two layers of read-only enforcement

The agent's SQL is untrusted input by design — an LLM writes it from a stranger's free-text question. So "read-only" isn't just a UI claim: an app-level guard rejects anything that isn't a single SELECT/WITH statement before it runs, and the query then executes as a dedicated mcp_readonly Postgres role with SELECT-only grants, a read-only transaction mode and a 5s statement timeout. The role is the layer that holds even if the guard has a bug.

Honest trade-off

Each reasoning step is a non-streaming call to the model — whether it's making a tool call or giving a final answer is only knowable once the response is complete. That costs some perceived latency per step, traded deliberately for what's actually worth watching live: discrete tool-call and tool-result events as they happen, instead of raw tokens of JSON being assembled.
